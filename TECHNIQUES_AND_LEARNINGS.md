## 2. Technique Deep-Dive: What Was Used & Why

### Technique 1: Decimal Digit Decomposition (`power in -4:3`)
#### What is it?
For every predictor variable (both numeric and ordinal-mapped categoricals), the value is decomposed across 8 powers of 10:
$$\text{digit}_{p}(x) = \left\lfloor \frac{x}{10^p} \right\rfloor \pmod{10}, \quad p \in \{-4, -3, -2, -1, 0, 1, 2, 3\}$$

#### Why use it? (Intuition & Learning Purpose)
1. **The Nature of Synthetic Data in Kaggle Playground**:
   - Tabular datasets in Playground competitions are generated by deep generative models (CTGAN, TVAE, or diffusion models) or decision-tree based samplers trained on an underlying ground-truth dataset.
   - These generators often produce subtle rounding artifacts, decimal precision cutoffs (e.g. exactly 1 or 2 decimal places, or distinct periodic digit distributions).
2. **Decision Tree Limitation on Continuous Variables**:
   - Decision trees perform single orthogonal threshold splits: $x > \theta$.
   - A tree **cannot easily test** whether "the tenths digit is 4" or "the hundredths digit is 0". To isolate a specific digit across a continuous range, a standard tree would need dozens of alternating splits:
     $$(0.4 \le x < 0.5) \lor (1.4 \le x < 1.5) \lor (2.4 \le x < 2.5) \dots$$
   - By extracting each decimal place as an explicit integer feature $0 \dots 9$, the GBDT can split on exact digit patterns in a single node!

### Technique 2: Normalized Frequency Encoding
#### What is it?
Counts how often each exact unique string representation of a value appears across the dataset, normalized by total samples:
$$\text{Freq}(x) = \frac{\sum_{i=1}^N \mathbb{I}(x_i = x)}{N}$$

#### Why use it?
- In real-world data and synthetic data alike, common values represent modal peaks (e.g. median defaults, rounded values like \$30,000 or commute of 5.0 km), while rare values represent extreme tails or outliers.
- Frequency encoding converts the "rarity" or "density" of a sample into a direct monotonic signal for tree models without requiring explicit 2D/3D kernel density estimation.

---

### Technique 3: Out-of-Fold Smoothed Target Encoding (TE)
#### What is it?
Encodes categorical and discrete values by the conditional target mean:
$$S_c = \frac{\sum_{i \in c} y_i + m \cdot \bar{y}}{N_c + m}$$
where:
- $N_c$ is the count of category $c$
- $\sum_{i \in c} y_i$ is the number of positive targets in category $c$
- $\bar{y}$ is the global target prior
- $m = 10$ is the additive Bayesian smoothing parameter

Crucially, on the training data, this is evaluated **strictly out-of-fold** using an inner 3-fold stratified cross-validation.

#### Why use it?
- High-cardinality or categorical variables often have non-linear relationships with the target probability that simple integer label encoding cannot communicate.
- Additive smoothing ($m = 10$) acts as a Bayesian shrinkage prior:
  - If a category has 2 samples ($N_c = 2$), its target encoding shrinks heavily toward the dataset prior $\bar{y}$.
  - If a category has 50,000 samples ($N_c = 50000$), the empirical conditional mean dominates.
- Inner cross-validation prevents **target leakage**, which otherwise causes GBDTs to overfit severely to the encoded target.

### Technique 4: 1280-Quantile Neighbor Target Encoding (`neighbor_qte`) with Gaussian Kernel Smoothing
#### What is it?
This is the most innovative feature in the Zoom Zoom pipeline, applied to `Annual_Income_USD`:
1. Slices the continuous variable into $q = 1280$ quantile intervals using empirical percentiles.
2. In each quantile bin $b$, computes:
   - Quantile relative position: $\text{pos}(b) = \frac{b}{q - 1}$
   - Bin central smoothed target rate:
     $$\text{center}(b) = \frac{\text{sum}_b + 10 \cdot \bar{y}}{\text{count}_b + 10}$$
   - **Neighbor-smoothed target rate** using a 3-tap Gaussian kernel:
     $$k = \exp\left( -0.5 \left( \frac{\Delta}{\sigma} \right)^2 \right) \quad \text{for } \Delta \in \{-1, 0, 1\}, \ \sigma = 0.8$$
     This yields kernel weights: $[k_{-1} \approx 0.4578, \ k_0 = 1.0, \ k_1 \approx 0.4578]$.
     
     The neighbor target sum and count are convolved:
     $$\text{ns}_b = k_{-1} \cdot \text{sum}_{b-1} + k_0 \cdot \text{sum}_b + k_1 \cdot \text{sum}_{b+1}$$
     $$\text{nc}_b = k_{-1} \cdot \text{count}_{b-1} + k_0 \cdot \text{count}_b + k_1 \cdot \text{count}_{b+1}$$
     $$\text{neighbor}(b) = \frac{\text{ns}_b + 10 \cdot (\sum k) \cdot \bar{y}}{\text{nc}_b + 10 \cdot (\sum k)}$$

#### Why use it?
- Standard target encoding cannot be directly applied to continuous variables like income because continuous floats have few exact matches.
- Binning into 1280 quantiles allows high resolution, but individual bins might have high variance or sparse sample counts.
- Applying a Gaussian kernel convolution across adjacent quantile bins shares statistical strength across neighboring income bands, functioning as an ultra-fast, non-parametric 1D kernel regression of target probability!

### Technique 5: LightGBM Hyperparameter Configuration for Multi-Resolution Features
The parameters selected in Zoom Zoom are specifically tailored for this 146-feature representation:

```python
lgb_params = {
    'objective': 'binary',
    'metric': 'auc',
    'learning_rate': 0.02,
    'max_depth': 5,
    'num_leaves': 247,
    'min_data_in_leaf': 10,
    'feature_fraction': 0.3029,  # Key: aggressive feature subsampling!
    'bagging_fraction': 0.8128,
    'bagging_freq': 1,
    'lambda_l1': 0.0709,
    'lambda_l2': 2.033,
    'max_bin': 1024,             # Key: high bin resolution!
    'seed': 60
}
```

#### Why these parameters matter:
1. **`feature_fraction = 0.3029` (30% per tree)**:
   - With 146 features (where 104 are digit decompositions), if a tree sampled 100% of features, strong linear predictors (like raw income or home charging) would dominate every split.
   - Subsampling only ~44 features per tree forces trees to find orthogonal, subtle non-linear interactions among the digit and frequency features, maximizing ensemble diversity across the boosting iterations.
2. **`max_bin = 1024`**:
   - Default LightGBM uses 255 bins. With 1280 quantile bins and multi-decimal features, 255 bins causes severe information loss (quantization noise). Setting `max_bin = 1024` retains fine-grained boundaries.
3. **`max_depth = 5`**:
   - Prevents overfitting on the fine-grained digit representations, ensuring shallow, high-confidence decision rules.

### Technique 6: Rank Transformation & Blending
#### What is it?
Converts raw probability predictions into normalized percentile ranks:
$$\text{rank}_{01}(p) = \frac{\text{rank}(p) - 0.5}{N}$$

#### Why use it?
- ROC AUC is an **order-based** metric (concordance probability: $P(p_1 > p_0)$). It depends solely on the relative ordering of predictions, not their calibration.
- When blending LightGBM with XGBoost or Neural Nets:
  - Different architectures output predictions with different sigmoid calibration curves and log-odds slopes.
  - A linear average of raw probabilities ($0.5 \cdot p_{\text{lgb}} + 0.5 \cdot p_{\text{xgb}}$) can be dominated by whichever model has a wider variance or heavier tails.
  - Rank normalization standardizes both models to a uniform distribution $U[0, 1]$, allowing clean, unbiased ensembling.

## 3. Practical Summary & Takeaways for Competitions

1. **Synthetic data has unique properties**: Never treat synthetic competition tabular data as purely continuous physical measurements. Generative models leave distinct structural signatures in decimal places, exact frequencies, and duplicate counts.
2. **Multi-resolution feature engineering**: Combining macro features (raw continuous), meso features (1280-quantile kernel smoothed rates), and micro features (decimal digit places) provides tree models with views across different scales.
3. **Low feature fraction for wide feature sets**: When generating 100+ fine-grained features, dropping `feature_fraction` to 0.30 - 0.40 is mandatory to prevent feature starvation and induce tree diversity.
4. **Rank calibration for diverse ensembles**: When combining models with fundamentally different inductive biases (LightGBM on multi-scale features + XGBoost on DGP generator formulas), rank-averaging or logit-space calibration is essential to preserve pairwise ordering.
